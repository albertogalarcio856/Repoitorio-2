Conceptos

# Concepto Definición
1Front-endCapa del software con la que interactúa el usuario; incluye la interfaz, sus estilos y su comportamiento en el navegador o dispositivo.
2Back-endCapa del software que procesa la lógica de negocio y los datos en el servidor.
3ComponentePieza reutilizable e independiente de la interfaz (botón, campo, tarjeta, tabla, modal, mapa).
4Diseño atómicoMetodología que organiza la interfaz en átomos, moléculas, organismos, plantillas y páginas.
5HTML5 semánticoUso de etiquetas que describen el significado del contenido (header, nav, main, footer).
6SVGFormato de gráficos vectoriales basado en XML; permite dibujar un mapa como un conjunto de trazos (path) que se pueden estilizar y programar.
7CSS3Lenguaje de hojas de estilo que define la presentación visual de un documento HTML.
8Variables CSS (custom properties)Valores reutilizables definidos en CSS, como colores o tamaños de la guía de estilos.
9FlexboxModelo de CSS para distribuir elementos en una dimensión (fila o columna).
10CSS GridModelo de CSS para distribuir elementos en dos dimensiones (filas y columnas).
11Diseño adaptable (responsive design)Interfaz que se ajusta a distintos tamaños de pantalla.
12Mobile firstEstrategia que diseña primero para pantallas pequeñas y luego amplía a pantallas mayores.
13BreakpointAncho de pantalla en el que cambia la distribución de la interfaz.
14Media queryRegla CSS que aplica estilos según las características del dispositivo.
15Tailwind CSSFramework de CSS de tipo utility-first: se construye la interfaz combinando clases pequeñas de un solo propósito (p-4, flex, text-lg).
16Utility-firstEnfoque de estilos basado en clases utilitarias aplicadas directamente en el HTML, en lugar de escribir CSS propio por componente.
17@themeDirectiva de Tailwind CSS v4 que define los tokens del proyecto (colores, tipografías, espaciados) y genera clases a partir de ellos.
18ViteHerramienta de desarrollo que crea, sirve y empaqueta proyectos front-end modernos.
19DOM (Document Object Model)Representación en árbol de una página que JavaScript puede leer y modificar.
20EventoAcción del usuario o del sistema (clic, envío, tecla) a la que el código puede responder.
21Delegación de eventosTécnica que usa un solo escuchador en un elemento padre para atender los eventos de muchos hijos.
22JSONFormato ligero de intercambio de datos basado en pares clave-valor.
23API RESTServicio web que expone datos y operaciones mediante peticiones HTTP.
24Vue.jsFramework progresivo de JavaScript para construir interfaces de usuario con componentes reactivos.
25Componente de archivo único (SFC)Archivo .vue que reúne la lógica (script), la plantilla (template) y los estilos de un componente.
26ReactividadCapacidad de Vue de actualizar la pantalla automáticamente cuando cambian los datos (ref, reactive, computed).
27DirectivaAtributo especial de Vue que aplica comportamiento a la plantilla (v-if, v-for, v-model, v-on).
28Props y emitsDatos que un componente recibe de su padre (props) y eventos que envía hacia su padre (emits).
29Vue RouterLibrería oficial de Vue para navegar entre vistas mediante rutas.
30ComposableFunción de Vue que encapsula lógica reutilizable con estado (por ejemplo, useDatos).
31Mapa interactivoInterfaz en la que el usuario selecciona zonas de un mapa para consultar su información.
32Mapa coropléticoMapa que colorea cada zona según el valor de un dato, acompañado de una leyenda.
33GeoJSONFormato JSON para representar formas geográficas, como los límites de los municipios.
34LeafletLibrería de JavaScript para mapas interactivos con teselas (por ejemplo, de OpenStreetMap).
35PWA (aplicación web progresiva)Aplicación web que puede instalarse y funcionar como aplicación móvil.
36GitSistema de control de versiones distribuido.
37CommitRegistro de un conjunto de cambios en el repositorio, con mensaje y autor.
38Rama (branch)Línea de desarrollo independiente dentro de un repositorio.
39Pull requestSolicitud para integrar los cambios de una rama, revisada por otro desarrollador.
40W3CConsorcio que define los estándares de la web (HTML, CSS, accesibilidad).
41WCAG 2.1Pautas de accesibilidad para el contenido web; el nivel AA es el exigido en esta guía.
42ARIAAtributos que mejoran la accesibilidad de componentes dinámicos para tecnologías de asistencia.
43LighthouseHerramienta del navegador Chrome que audita rendimiento, accesibilidad y buenas prácticas.
44Matriz de fidelidadComparación pantalla por pantalla entre el prototipo aprobado y la interfaz construida.
45CoevaluaciónValoración que hacen los compañeros del desempeño de un aprendiz o de un equipo, con criterios conocidos de antemano.
46Ambiente de formaciónEspacio físico donde se dicta un curso (aula, salón, laboratorio o auditorio). Es el término que usan los documentos de requisitos del proyecto; en esta guía aula y ambiente se usan como sinónimos.
47FichaNúmero que identifica un grupo de aprendices que cursa un programa de formación.
48Franja horariaIntervalo de tiempo de un día (por ejemplo, lunes de 07:00 a 13:00) en el que se dicta un curso.
49Cruce de horarioConflicto que ocurre cuando un aula o un instructor quedan asignados a dos cursos en franjas que se superponen el mismo día.
50Guardia de navegaciónFunción de Vue Router que se ejecuta antes de entrar a una ruta y permite restringir el acceso según el rol del usuario.
51PaginaciónDivisión de una lista larga de resultados en páginas, con controles para avanzar, retroceder o ir a una página concreta.
52DER (documento de especificación de requisitos)Documento del proyecto que lista los requisitos funcionales (RF) y no funcionales (RNF) del software.
